# Personal Tree — план разработки на Flutter (по ТЗ)

> «Посади сегодня, дыши завтра». Пользователь выбирает вид дерева в каталоге, оформляет заказ, исполнитель подтверждает реальную посадку, а пользователь отслеживает своё дерево в «Моём лесу» и на карте Алматы.

**Сквозной сценарий, который должен показать прототип:**
регистрация → выбор дерева → оформление заказа → подтверждение посадки исполнителем → отслеживание своего дерева.

**Главное правило ТЗ:** данные о реальной посадке (фото, дата, координаты, статус «посажено») появляются **только после подтверждения ответственным исполнителем** в админ-панели. Клиент сам не может менять эти поля, это обеспечивается правами доступа на сервере.

---

## 1. Как ТЗ соотносится с презентацией

| Тема | Презентация | ТЗ (берём за основу) | Решение |
|---|---|---|---|
| Модель покупки | Накопительные взносы до 100 % | Покупка дерева из каталога, можно выбрать количество | В MVP — покупка из каталога. Накопление (кольцо прогресса) переносим в этап 3 как вариант «копилка» |
| Оплата | Сразу | На следующем этапе | В прототипе и MVP заказ оформляется без оплаты или с тестовой оплатой |
| Геймификация | Рост дерева | Достижения и эко-баллы | Эко-баллы и бейджи в профиле |
| Партнёры / доставка | Вход через delivery-сервис | Не упоминается | Откладываем на этап после MVP |
| Визуальный стиль | Зелёные тона | Зелёный, белый, светло-бежевый, минимализм | Дизайн-система в этих цветах |

## 2. Экраны приложения (по ТЗ)

**0. Авторизация.** Splash, онбординг (2–3 слайда об идее), регистрация и вход (email/пароль или телефон+OTP, Google/Apple — опционально).

**1. Главная (Home).** Логотип, «Привет, {имя}», счётчик посаженных деревьев (личный и по городу), кнопка «Посадить дерево» (ведёт в каталог), карточки статистики вклада (деревья, CO₂ в год, эко-баллы), блок «О проекте».

**2. Каталог (Tree Shop).** Сетка/список видов: фото, название, короткое описание, стоимость посадки, кнопка «Выбрать дерево». Опционально фильтры.

**3. Покупка дерева.** Выбранный вид (фото, описание), цена, блок «Что входит в посадку» (саженец, посадка, доставка, уход и полив, цифровое отслеживание — из финмодели презентации), степпер количества, итоговая сумма, кнопка «Подтвердить заказ», экран успеха.

**4. Мой лес (My Forest).** Список деревьев: индивидуальный номер (например `PT-ALM-000123`), фото (заглушка до посадки), дата посадки, место, бейдж статуса. Детальная карточка дерева с таймлайном статусов и мини-картой.

**5. Карта (Map).** Интерактивная карта Алматы с маркерами посадок (кластеризация). Свои деревья выделены цветом. По тапу — bottom sheet: номер, вид, дата, адрес/зона, фото, переход в карточку.

**6. Профиль.** Имя и аватар, количество деревьев, общая статистика вклада, история заказов, достижения и награды (сетка бейджей, полученные/закрытые), настройки и выход.

**Навигация:** нижний таб-бар — Главная · Каталог · Мой лес · Карта · Профиль.

## 3. Статусы

**Заказ:** `created` → `confirmed` (принят оператором) → `completed` / `cancelled`.

**Дерево** (создаётся по одному на каждую единицу в заказе):

| Статус | Что видит пользователь | Кто меняет |
|---|---|---|
| `awaiting_planting` | «Ожидает посадки», фото-заглушка, без координат | Создаётся автоматически при заказе |
| `planted` | «Посажено»: фото, дата, координаты, исполнитель | **Только исполнитель/админ** с обязательными фото и геоточкой |
| `monitoring` | «На мониторинге»: лента обновлений (полив, фото роста) | Только исполнитель/админ |

---

## 4. Достижения и эко-баллы

- **Баллы:** например +100 за каждое посаженное дерево (начисляются после подтверждения, а не при заказе), +20 за регистрацию, бонусы за серии.
- **Бейджи:** «Первый росток» (1 дерево), «Маленькая роща» (5), «Лесник» (10), «Разнообразие» (3 разных вида), «Первопроходец» (в числе первых 100 пользователей).
- **Статистика вклада:** CO₂ — условно ~22 кг на дерево в год (указать, что значение примерное). Также площадь озеленения и баллы.
- Логика начисления живёт на сервере (триггер или функция при переходе дерева в `planted`).

## 5. Административная панель

Делаем на **Flutter Web** (общие модели и код с мобильным приложением) или на старте берём готовую админку: Supabase Studio / Retool / Appsmith.

Функции из ТЗ:
1. **Виды деревьев:** CRUD — название, описание, фото, цена, состав посадки, активен/скрыт.
2. **Заказы:** список с фильтрами, детали, подтверждение/отмена.
3. **Посадки:** выбор деревьев со статусом `awaiting_planting` → форма «Подтвердить посадку»: дата, точка на карте, фото (обязательно), исполнитель. Можно сразу на группу деревьев.
4. **Фото:** загрузка снимков посадки и мониторинга в Storage.
5. **Статусы:** `planted` → `monitoring`, добавление записей ухода.
6. **Статистика:** пользователи, заказы, деревья по статусам, посадки по месяцам, топ видов.

**Роли:** `user`, `planter` (исполнитель — подтверждает посадки и загружает фото), `admin` (всё).

## 6. Технический стек

| Слой | Выбор |
|---|---|
| Клиент | Flutter 3.x (iOS, Android) + Flutter Web для админки |
| Архитектура | Feature-first, слои data / domain / presentation |
| Состояние | Riverpod (`riverpod_generator`) |
| Навигация | `go_router` + `StatefulShellRoute` для таб-бара |
| Модели | `freezed` + `json_serializable` |
| Бэкенд | **Supabase**: Postgres, Auth, Storage, Row Level Security, Edge Functions. Это самый быстрый путь при стартовом бюджете 270 000 ₸ |
| Карта | `flutter_map` + OpenStreetMap (бесплатно), кластеры — `flutter_map_marker_cluster`. Альтернатива — 2GIS / Google Maps |
| Изображения | `cached_network_image`, `image_picker` (админка) |
| Уведомления | FCM — «Ваше дерево посажено!» (этап 3) |
| Оплата (этап 3) | Kaspi Pay / FreedomPay / CloudPayments через вебхук на сервере |
| Локализация | ru (основной), kk, en |
| Качество | `very_good_analysis`, unit/widget/integration-тесты, Crashlytics/Sentry |
| CI/CD | GitHub Actions или Codemagic, flavors `dev` / `prod` |

## 7. Модель данных

```
profiles        id (= auth.uid), name, avatar_url, role, eco_points, created_at
tree_species    id, name, description, photo_url, price, includes jsonb, co2_per_year, is_active
orders          id, user_id, status, total_amount, created_at
order_items     id, order_id, species_id, quantity, unit_price
trees           id, code (PT-ALM-000123), owner_id, order_id, species_id, status,
                planted_at, lat, lng, location_name, planted_by, confirmed_at
tree_photos     id, tree_id, url, kind (planting|monitoring), taken_at, uploaded_by
tree_events     id, tree_id, type (planted|watered|checked|note), note, created_at, author_id
achievements    id, code, title, description, icon, condition jsonb
user_achievements user_id, achievement_id, earned_at
```

**RLS-политики:** пользователь читает только свои `orders` и `trees` (на общей карте — только обезличенные координаты посаженных деревьев). Изменять `trees.status`, `planted_at`, `lat`/`lng` и добавлять `tree_photos` могут только `planter`/`admin`.

## 9. Этапы (как в ТЗ)

### Этап 1. UI/UX-прототип — 2–3 недели
**Цель:** показать весь путь пользователя на рабочем, кликабельном приложении.

1. Дизайн-система в Figma: цвета (зелёный `#2F5D3A`, белый, бежевый `#F4EFE6`), шрифты, кнопки, карточки, бейджи статусов.
2. Макеты всех 6 экранов, экранов авторизации и 3 экранов админки (заказы, подтверждение посадки, виды).
3. **Flutter-прототип на моковых данных** (in-memory репозитории):
   - полный путь: регистрация → каталог → заказ → «Ожидает посадки»;
   - демо-переключатель «Режим исполнителя», чтобы на показе подтвердить посадку и увидеть, как дерево становится «Посажено» с фото и точкой на карте;
   - карта Алматы с демо-маркерами.
4. Демонстрация, сбор отзывов, правки.

Результат: APK/TestFlight-сборка и ссылка на Figma.

### Этап 2. MVP — 4–6 недель
1. Supabase: схема, RLS, Storage, сиды видов деревьев.
2. Реальная регистрация/вход, профиль.
3. Каталог и экран покупки из БД.
4. Заказы без оплаты: создание заказа → генерация деревьев с кодами `PT-ALM-…` → «Мой лес».
5. История заказов в профиле.
6. Минимальная админка: виды деревьев, заказы, подтверждение посадки с фото и координатами.
7. Тесты ключевой логики, бета-тест на 20–50 пользователях.

### Этап 3. Расширение функционала — 4–6 недель
1. Подключение оплаты (вебхуки, чеки, оферта). Заказ становится `confirmed` только после успешного платежа.
2. Полноценная интерактивная карта: кластеры, фильтры, свои/все деревья.
3. Мониторинг: статус `monitoring`, лента событий ухода, фото роста.
4. Достижения и эко-баллы, push-уведомления.
5. Полная админ-панель со статистикой и ролями `planter`/`admin`.
6. Публикация в App Store / Google Play.

### Дальше (из презентации)
Накопительная «копилка» на дерево, интеграция с delivery-партнёрами, корпоративные ESG-кабинеты, школьные рощи, расширение на другие города Казахстана.

## 10. Риски

| Риск | Решение |
|---|---|
| Пользователь не верит, что дерево посажено | Обязательные фото и геоточка при подтверждении, имя исполнителя, публичная карта |
| Статус «посажено» без реальной посадки | Права на сервере (RLS) — менять может только `planter`/`admin`, журнал изменений |
| Сезонность посадок | Ожидаемый срок посадки на экране «Ожидает посадки» |
| Правила сторов для оплаты | Оформлять как услугу посадки (юрлицо, оферта), заранее проверить у юриста |
| Небольшой бюджет | Supabase + Flutter Web админка, без своего бэкенда |
